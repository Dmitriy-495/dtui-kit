# Архитектура dtui (проект, кода пока нет)

Статус: **черновик для обсуждения.** Дополняет `PHILOSOPHY.md`. Первый
потребитель и пилот — `dtrader-history-tui`.

## 1. Слои

```
dtui-kit      независимые компоненты: banner, цифры/часы, sparkbar, theme...
   ▲          (ничего не знают про layout и друг про друга)
dtui          layout-движок: читает дерево из theme.yaml, раскладывает
   ▲          компоненты по зонам, передаёт им размер, свойства и данные
приложение    theme.yaml (дерево layout + свойства) и источники данных
```

- **`dtui-kit`** — библиотека готовых компонентов. Каждый принимает
  общий набор свойств (раздел 3) и не зависит от остального.
- **`dtui`** — минимальный фреймворк: интерпретатор дерева layout.
  **Пока живёт внутри приложения** (пакет `internal/dtui`) и не импортирует
  код приложения. Выносится в отдельный проект, когда его захочет второй
  потребитель (правило 3 из `PHILOSOPHY.md`): вынос = перенос папки.
- **Приложение** — свой `theme.yaml` с деревом layout и значениями
  (`bind`). Логика, которую нельзя выразить декларативно, остаётся в Go.

## 2. Контракт компонента

Компонент получает свойства, **внешний** размер зоны и данные, а
возвращает строку. Размер он не выбирает, его задаёт layout (в lipgloss v2
`Width`/`Height` уже включают рамку).

```go
// эскиз, не финальный API
type Component interface {
    Render(p Props, width, height int, data Data) string
}
```

## 3. Общие свойства и на чём они держатся

Минимум, нужный всем компонентам; новые добавляем по одному, по мере нужды.

| Свойство | Смысл | Готовое решение |
|---|---|---|
| `font` | имя FIGlet-шрифта | `go-figure` |
| `font-size` | `sm` / `md` / `lg` → шрифт по высоте | своя шкала в ките |
| `font-color` | имя из палитры (`brand`, `ok`, `data`, `muted`) или код | `lipgloss` + `theme` |
| `bold` | жирность | `lipgloss` |
| `margin`, `padding` | отступы в клетках терминала | `lipgloss` |
| `align`, `position` | выравнивание внутри ячейки | `lipgloss` |
| `show-from` | минимальная ширина терминала для показа | свой, одна строка |

Чтение YAML — `goccy/go-yaml`. Ошибка в имени ключа, типа или свойства
даёт **ошибку при старте**, а не молчаливое игнорирование.

## 4. Дерево layout в theme.yaml (набросок)

```yaml
layout:
  - zone: header
    row:
      - { type: banner, text: dtrader, font-size: lg, font-color: brand }
      - { type: banner, text: history, font-size: md, font-color: brand, show-from: 160 }
      - { type: clock,  font-size: sm,  font-color: ok, align: right }
      - { type: text,   bind: snapshots_total, font-color: data, margin-top: 1, align: right }
  - zone: body
    cols:
      - { zone: content,  width: 50%, type: table }
      - { zone: rightbar, width: 50%, column: [ {type: sparkbar, bind: cpu}, {type: sparkbar, bind: ram} ] }
  - zone: footer
    row: [ { type: text, bind: status, font-color: ok } ]
```

Стандартные зоны: `header`, `content`, `leftbar`, `rightbar`, `cmdline`,
`footer`. Приложение выбирает нужные; остальные необязательны.

## 5. Данные

Элементу нужны значения (CPU, число снапшотов). Приложение отдаёт их по
именам (`bind`), компонент берёт нужное. Это единственное новое понятие
помимо свойств.

## 6. Бюджет сложности (защита от самодельного CSS)

Язык описания layout ограничен: **строка, колонка, ширина (в процентах или
клетках), выравнивание.** Остальное — Go-код приложения. Если пилот требует
заметно больше ~300 строк движка или нового вида контейнера, останавливаемся
и пересматриваем подход, а не растим язык.

## 7. План

1. **Пилот: шапка `dtrader-history-tui`** из YAML (логотип, подпись, часы,
   счётчик). Остальной экран пока как есть.
2. Критерий успеха: шапка выглядит так же, как сейчас, а её вид меняется
   правкой `theme.yaml` без пересборки.
3. Расширяем на `body` и `footer`.
4. Выносим `internal/dtui` в проект `dtui`, когда придёт второй потребитель.

## 8. Открытые вопросы

- **Цифры и часы.** Какой набор шрифтов понимает кит: встроенные FIGlet,
  внешние `.flf` (например ANSI Shadow) или собственный пакет `digits`
  (семисегментные, 3 строки). Решается отдельно от схемы YAML.
- **Шкала `font-size`:** какому шрифту соответствуют `sm`/`md`/`lg`.
- **Имя проекта `dtui`** рядом с `dtui-kit` легко путается. Решить при вынесе.
- **Единицы `margin`/`padding`:** клетки терминала (принято по умолчанию).
