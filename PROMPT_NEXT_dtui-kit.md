# dtui-kit — чекпоинт и передача в новый чат (2026-10-07)

## Кто ты и что происходит

Брат, привет! Ты — новый Клод, продолжающий работу над `dtui-kit` —
общей библиотекой компонентов для консольных интерфейсов (TUI) семейства
проектов dtrader. Это вспомогательная инфраструктура, а не торговый
проект. У тебя нет памяти о прошлых сессиях: этот документ + сам
репозиторий `github.com/Dmitriy-495/dtui-kit` (публичный, клонируется
по HTTPS) — весь контекст. **Сначала прочитай в репозитории
`PHILOSOPHY.md` и `ARCHITECTURE.md`** — это решения автора, не
пересматривай их без его слова.

## Карта семейства (чтобы понимать, зачем кит)

| Проект | Что это | Состояние |
|---|---|---|
| `dtrader-history` | сборщик снапшотов order book на VPS (Go) | **в бою**, копит данные 3 месяца |
| `dtrader-history-tui` | TUI-монитор сборщика (Go, bubbletea) | **в бою**, единственный потребитель кита (`v0.3.0`) |
| `dtui-kit` | **этот проект**: библиотека компонентов | выполняет функции, `v0.3.0` |
| `dtrader-tui-6` | боевой TUI торгового бота | ждёт 3 месяца исторических данных; сидит на `dtui-kit v0.1.0` + Charm v1 |

У каждого проекта свой чат, чтобы не отвлекать основную работу
(автоматическую торговлю) на UI.

## Философия (кратко, полный текст — в `PHILOSOPHY.md`)

1. Кит — **клей, а не фреймворк**: опираемся на bubbletea/bubbles/lipgloss
   открыто, не переписываем то, что они умеют.
2. **Сначала ищем готовое** (реальным веб-поиском, не по памяти); своё
   пишем, только когда готового нет, и записываем причину.
3. Добавляем **только после боя** (минимализм автора: «минимализм — это
   красиво»). Layout выносим, лишь когда его захочет второй потребитель.
4. Мелкие сторонние библиотеки прячем за своим API (пример: `go-figure`
   в `banner`); ядро Charm не прячем.

Автор прямо сказал: **не копируем Tailwind** — берём только идею «стили
вынесены из кода».

## Что сделано (состояние `v0.3.0`)

Теги: `v0.1.0` (4 пакета), `v0.2.0` (переезд на Charm v2, удалён `align`),
`v0.3.0` (`FontBanner3`). 36 тестов проходят, ~450 строк кода.

- **`theme`** — фирменная палитра (оранжевый `border = "214"`, `ok 82`,
  `warn 226`, `sos 196`, `data 214`, `muted 239`), переопределяется
  `theme.yaml` (`theme.Load`/`LoadIfExists`, см. `theme.example.yaml`).
  После переезда на lipgloss v2 экспортируемые цвета имеют тип
  `color.Color` (раньше `lipgloss.Color`) — это ломающее изменение API.
- **`sparkbar`** — вертикальный бар-чарт истории метрики на `▁▂▃▄▅▆▇█`
  (`History`, `Render`, `RenderStyled` с порогами warn/sos). Используется
  для CPU/RAM/DISK в `dtrader-history-tui`.
- **`banner`** — FIGlet-заголовки поверх `go-figure`; наружу не торчит
  ни одного типа `go-figure`. Проверенные шрифты (`Fonts()`): standard,
  small, slant, mini, big, **banner3**. `MustRender` паникует на
  неизвестном шрифте, `Render` — нет, но `go-figure` на непроверенном
  имени может вызвать `log.Fatal` (прямой выход из программы). Формат
  `.tlf` не поддерживается, часть внешних `.flf` роняет парсер.
- **`align` удалён** (v0.2.0): оказался дублем `lipgloss` (`Style.Width().
  Align()`) и ошибался на широких символах и цветном тексте
  (`len([]rune)` вместо ширины). Потребителей не было.
- **Переезд на Charm v2** (lipgloss v2.0.6). Go ≥ 1.25.
- **Документы**: `PHILOSOPHY.md`, `ARCHITECTURE.md`, `README.md`.

## Принятые решения (не переоткрывай)

- `sparkbar` оставляем своим: `ntcharts` v2 (Go 1.26.8, тяжёлый
  canvas-подход) явного выигрыша не даёт; если когда-нибудь понадобятся
  многострочные графики или оси — брать `ntcharts`, а не писать своё.
- **Layout живёт в приложении**, а не в ките. Движок раскладки пока —
  пакет `internal/dtui` внутри `dtrader-history-tui` (без импортов кода
  приложения); выносим в проект `dtui`, когда придёт второй потребитель.
- Шкала `font-size`: `sm`=small, `md`=standard, `lg`=banner3 (таблица в
  движке приложения).
- Контракт компонента (эскиз): получает свойства, **внешний** размер и
  данные, возвращает строку; про layout и соседей ничего не знает.
  Общие свойства: `font`, `font-size`, `font-color`, `bold`, `margin`,
  `padding`, `align`, `show-from`.

## Что предстоит

1. **README**: обновить — `FontBanner3`, Charm v2 / Go ≥ 1.25, ссылки на
   `PHILOSOPHY.md` и `ARCHITECTURE.md`, строка про «Tailwind» в разделе
   `banner` противоречит философии.
2. **Цифры и часы (открытый вопрос).** Автор хочет «цифровые» ANSI-цифры
   не только в часах, но и в других компонентах (количество, цена).
   Сейчас часы — шрифт `small` с ячейками фиксированной ширины (в
   движке приложения). Варианты, которые обсуждались:
   - своё: 3-строчные семисегментные глифы `0-9 : . , -` (~35 колонок на
     часы); автор сказал, что **это выглядит приглядней всего**, а правило 2
     философии разрешает своё, если готового нет — нужно записать причину;
   - внешний `.flf` (`ANSI Shadow` — 6 строк, блоки; `Calvin S` — 3 строки,
     ноль с ромбом) — для этого `banner` надо научить грузить внешние
     шрифты (риски выше, лицензия `ANSI Shadow` неясна: автор шрифта «?»);
   - Unicode 13 «segmented digits» U+1FBF0–1FBF9: готовый стандарт, но
     1 ячейка × 1 строка и зависит от шрифта терминала (автор проверку
     `printf '\U0001FBF0…'` пока не прислал) — годится для цифр в таблице;
   - готовых компонентов в Charm/`ntcharts`/Bubble Tea экосистеме **нет**
     (проверено); `termdash` (`segdisp/sixteen`) — другой фреймворк.
   Если решишь делать пакет `digits`: фиксированная ширина ячеек (часы не
   должны «дёргаться»), цвет задаёт вызывающий через lipgloss.
3. **`theme.yaml` и `layout.yaml`**: сейчас раздельны (kit читает только
   свои ключи, а разбор раскладки строгий). Объединить, когда понадобится.
4. **Аудит `banner.Align`/`Width`**: ни один потребитель не использует.
   Не удаляй с налёта: `lipgloss.PlaceHorizontal` выравнивает каждую
   строку отдельно и искажает форму FIGlet-фигур — собственное
   выравнивание «по общему отступу» может быть оправдано. Проверь и реши.
5. **Миграция `dtrader-tui-6` на v2** (когда автор скажет; боевой TUI
   трогаем осторожно). Чек-лист из опыта `history-tui`:
   - импорты `charm.land/{bubbletea,bubbles,lipgloss}/v2`;
   - `View() string` → `View() tea.View` (`v.AltScreen = true` вместо
     `tea.WithAltScreen()`); `tea.KeyMsg` → `tea.KeyPressMsg`;
   - `lipgloss.Width/Height` у стиля с рамкой **включают рамку** (в v1 —
     нет): убрать ручные `width-2`/`height-2`;
   - у `bubbles/table` нужно **`SetWidth`** (иначе строки данных не
     рисуются), а `SetHeight` уже учитывает строку заголовка;
   - `lipgloss.Color` теперь функция; `SetColorProfile` убран.
6. Когда второй потребитель действительно придёт: вынести движок раскладки
   из `history-tui` в проект `dtui` (имя `dtui` рядом с `dtui-kit` легко
   путается — решить при вынесе).

## Справочник: высота × ширина FIGlet-шрифтов (слово `dtrader`)

Измерено по всем 144 встроенным шрифтам `go-figure`. Кегль в консоли — это
число строк; размер символов задаёт терминал.

| Строк | Шрифты (высота×ширина) |
|---|---|
| 2 | mini 2×32, short 2×15 |
| 3 | smshadow 3×48, digital 3×28 (цифры «в коробочках»), linux 3×37 |
| 4 | small 4×45, smslant 4×42, thick/thin/rectangles 4×35, chunky 4×46, shadow 4×50 |
| 5 | standard 5×51, slant 5×54, ogre 5×44, computer 5×42, block 5×75 |
| 6 | big 6×51, doom 6×44, graffiti 6×55 |
| 7 | **banner3 7×67** (сплошной `#`, логотип), banner4 7×68, larry3d 7×59 |
| 8+ | colossal 8×58, epic 8×63, univers 8×81, doh 17×141 |

`mini` на терминале автора «разваливается» из-за межстрочного интервала;
`lcd` пытается быть семисегментным, но нечитаем; `cybermedium` и
`cybersmall` не умеют цифры.

## Как автор принимает решения

- Отвечает коротко («ага», «го», «Вариант 3»); вопросы лучше задавать
  с 2–3 вариантами и **картинкой/превью**, а не абстрактно. Если он
  «не понял вопроса» — перескажи на примере его шапки.
- Часто присылает скриншоты терминала; оценивает на глаз («шикарно»,
  «корявенько»). Просит «пожирнее», «поднять на строку» — это CSS-мышление,
  и это нормально: см. `ARCHITECTURE.md`.
- Ценит, когда ты **проверяешь по сети и в коде**, а не по памяти; ценит
  честные оговорки («не проверил живой запуск»).
- Может оборвать фразу или перепутать название (`Standfr` = Standard) —
  называй своё понимание и двигайся, поправит.

## Окружение и грабли

- Модуль `github.com/Dmitriy-495/dtui-kit`; зависимости: lipgloss v2,
  `go-figure`, `goccy/go-yaml v1.19.2` (не `gopkg.in/yaml.v3`).
- **У автора**: Go 1.22.3 + `GOTOOLCHAIN=go1.27.1`, прокси
  `GOPROXY=https://goproxy.cn,direct` (бывают `TLS handshake timeout`).
  `GOSUMDB=off` **ломает** скачивание тулчейна — не советуй его для
  `go get` свежих версий; для своего кита можно `GONOSUMDB=github.com/Dmitriy-495/dtui-kit`.
- **В твоей песочнице**: нет доступа к `go.dev`, `proxy.golang.org`,
  `charm.land`; доступны `github.com`, `pypi.org`, `npmjs.org`. Go ≥ 1.26
  берётся так: `pip download go-bin --no-deps -d /tmp/pg && cd /tmp/pg &&
  unzip -o go_bin-*.whl -d x` (сторонняя переупаковка официальных сборок,
  только для проверки; у автора ставь официальный Go). `charm.land/*`
  недоступен — клонируй `charmbracelet/{lipgloss,bubbletea,bubbles}` и
  подключай через `replace`; `golang.org/x/*` — через зеркала
  `github.com/golang/*` (x/sys v0.47.0, x/sync v0.22.0). Исходники гайдов:
  `UPGRADE_GUIDE_V2.md` в репозиториях lipgloss и bubbletea.
- **Ты не можешь пушить** (нет учётных данных). Рабочий процесс: ты готовишь
  архив с **целыми файлами**, автор распаковывает его в `/tmp` и копирует в
  репозиторий, затем `go vet && go test`, коммит, пуш, тег. Патчи из чата
  не работают: при копировании табы превращаются в пробелы. Распаковывать
  прямо в репозиторий нельзя (появляется лишняя вложенная папка).
- Тесты `go test` идут без TTY: проверяй не только «зелёное», но и **вид**
  (A/B-сравнение: символ + цвет + жирность по ширинам терминала).
- Каждое изменение публичного API `theme`/`sparkbar` — ломающее для
  реального потребителя: обратная совместимость, либо явный план
  миграции и новая версия. Версии: правка API = минорный тег (`v0.4.0`).
